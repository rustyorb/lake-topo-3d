# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — `tsx server.ts`: one process serving the Express API and the Vite dev middleware (HMR). There is no separate frontend server. Default port 3000, probes upward if busy; set `PORT` in `.env`.
- `npm run lint` — `tsc --noEmit`. There is no ESLint/Prettier.
- `npm run verify` — four scripts under `scripts/`, the only automated tests; each exits non-zero on failure and can be run alone with `npx tsx scripts/<name>.ts`. `verify-stl` builds meshes from a synthetic grid and asserts the STL is a closed 2-manifold (every edge shared by exactly two opposite-direction triangles), has positive signed volume, puts north at +Y, and that the land/lake split parts are each closed and sum to the whole volume; the 3MF container must have a valid zip signature. `verify-structure` plants a hole pair, hump, breakline, point and flat in a synthetic lake and asserts each is detected near its planted cell. `verify-layers` asserts every laser-pack ring closes, the shoreline sheet keeps the land fraction, and sheets shrink monotonically up the stack. `verify-soundings` rasterises 300 random soundings of a known bowl and asserts interior RMSE under 0.8 m, shore near zero, and no cell deeper than the deepest sounding. Run them after touching `src/utils/stlExporter.ts`, `src/lib/structure.ts`, `src/lib/layers.ts` or `server/soundings.ts`.
- `npm run check` — lint + verify.
- `npm run build` — `vite build` for the SPA, then esbuild bundles the server to `dist/server.cjs` (`--packages=external`, so `node_modules` must exist at runtime). `npm start` serves it with `NODE_ENV=production`.
- Manual API smoke test against a running dev server: `curl "http://localhost:3000/api/lake-terrain?q=Deam%20Lake,%20Indiana&gridSize=96"`. Add `&offline=true` to skip every network lookup. Delete `.cache/` (or run with `LAKE_CACHE_DISABLED=true`) to force fresh lookups.
- `bun.lock` is the lockfile; `bun install` is the fastest way to install, `npm install` also works.

## Architecture

Single-process local app: browser SPA (React 19 + Three.js) → Express API in `server.ts` → public geodata services and, optionally, Gemini. The browser never talks to Gemini or OSM directly.

**Data pipeline (`server/lakeService.ts`, `generateLakeTerrainGrid`)** — the core of the app. Three independent axes, each with its own fallback chain, and the result carries a label for each (`geometrySource`, `demSource`, `bathymetrySource`, `generationMethod`, `depthIsEstimated`):

1. *Shoreline*: `server/geoData.ts` `lookupLakeOSM` (Nominatim, throttled to 1 req/s, disk-cached). Indiana fallback when the geocoder is down: `findIdnrOutlineByName`. Offline: hand-built Deam Lake SDF or a procedural blob (the `shape`/`terrainProfile` fields of `MIDWESTERN_LAKES` in `server/lakeData.ts` only drive this path; online only its `metadata` is used). When an IDNR survey is found, the DNR's NHD outline replaces the OSM polygon as the shoreline so the contours stay inside the shore.
2. *Elevation*: `server/dem3dep.ts` (USGS 3DEP ImageServer, float32 GeoTIFF decoded in-house, US only) → `server/geoData.ts` `sampleDem` (Terrarium tiles, worldwide). Lake surface elevation = median DEM inside the shoreline.
3. *Bathymetry*: `server/idnrBathymetry.ts` — IDNR sonar contours from the IndianaMap feature service, rasterised by `rasterizeContourDepths` (deepest enclosing closed contour = floor, linear interpolation to the next deeper line, exponential rise inside the innermost ring). Elsewhere: distance-to-shore bowl scaled to max depth (`buildRealTerrain`). User soundings (`POST` body `soundings`, `server/soundings.ts` `rasterizeSoundings`: inverse-distance-squared over the 12 nearest samples with the shoreline as zero-depth samples, then two 3×3 mean passes) beat both when 3+ fall inside the shoreline; the result is `bathymetrySource = 'user-soundings'`, ships no `surveyContours`, and the sounding list is hashed into the cache key.

Max depth precedence: IDNR survey > curated `server/lakeData.ts` > Wikipedia infobox / Wikidata (`server/wikiData.ts`) > uploaded-chart reading > LLM recon > `estimateMaxDepthM(area)`. The optional LLM (`server/aiRecon.ts` over `server/llm.ts`) runs last and only fills gaps; sourced numbers are never overwritten. Mean depth defaults to 0.42 × max when no source supplies one. Curated/AI landmarks have no coordinates in the real frame, so they are kept with `normX/normY = NaN` (list only) and two computed markers (deepest cell, highest DEM cell) are added.

The IDNR contour layer has no reliable key to the outline layer; `fetchIdnrSurvey` queries contours by the outline's bounding box, keeps the ones whose `lake_name` matches the outline's GNIS name (falling back to lines that start inside the outline), then restricts to the most common `lake_name` so a neighbouring lake's lines don't leak in.

`framePad` (query/body option, default 0.28 of the lake's longer side) controls how much terrain surrounds the lake; the UI's "Lake only" frame sends 0.06. It is part of the terrain cache key.

Grid conventions everywhere: square `gridSize×gridSize`, row 0 = north edge, col 0 = west edge, `elevations` in metres MSL, `depths` in metres below `waterElevation`. Cells are not necessarily square in metres; `physicalWidthKm/HeightKm` carry the frame size. The server clamps the requested `gridSize` to 32–`MAX_GRID` (160; default 72 when omitted) and bumps it to 128 or 160 for large/branchy lakes regardless of what the client asked for. Results are cached in memory for an hour keyed by query+options; OSM, IDNR and Wikipedia lookups are cached on disk as one JSON file per namespace in `.cache/` (`server/diskCache.ts`; 14–30 day TTL, 500 entries per namespace, and IDNR misses are cached as `null`, so a failed lookup stays failed until the file is deleted).

**Shared math (`src/lib/contours.ts`)** — marching squares with edge interpolation plus segment joining, imported by both the server (SVG map) and the browser (3D contour lines). The scalar field used for contours is always "feet relative to the water surface" so the 0 level is the shoreline, positive levels are land, negative levels are depth.

**Native survey vectors** — when the lake has an IDNR survey, `lakeService` also ships `surveyContours` (the DNR polylines re-expressed in fractional grid coordinates, clipped to the frame) and `spotElevations` (local DEM maxima on land). The SVG map draws the native lines with repeated "24-foot" labels (`labelsAlong`) instead of re-contouring the grid for water, and `Lake3DViewer` drapes them on the bed when `useSurveyContours` is on. Land contours are always grid-derived. The SVG page layout lives in `src/lib/mapFrame.ts` and is shared with the browser so `TopoMapViewer` can place overlays and read the grid under the cursor.

**Fishing layer (`src/lib/structure.ts`, `src/components/FishingPanel.tsx`)** — `analyzeStructure(gridData)` runs in the browser in a `useMemo` (about 50 ms at 128²) and returns holes, humps, drop-offs, points, flats and saddles with grid position, lat/lon, depth, a one-line detail and a score; each detector is thresholded relative to the lake (80th-percentile slope for breaks, prominence over a ring mean for holes) so it degrades to "nothing found" on flat modelled bowls rather than inventing structure. Waypoints are localStorage per lake id (`src/lib/waypoints.ts`); GPX 1.1 export is `src/lib/gpx.ts`. `App.tsx` turns structure + waypoints into `markers` for both viewers; `Lake3DViewer` draws them as spheres/pins, raycasts them for hover/select, and flies the camera on `focusRequest`. A non-drag click is routed by `pickMode` (`src/lib/overlays.ts`: `none | pin | section`; shift-click is always a pin) through `onPick` to `App.tsx`, which drops a waypoint or sets the cross-section ends. The thermocline band tints vertex colours by true depth (not the terrace-shaped depth) and draws its two edge isolines in amber.

**Angler tools** — all client-side, all drawn through one `overlays: OverlayLine[]` prop (fractional grid polylines with a colour) that `Lake3DViewer` drapes on the boosted surface and `TopoMapViewer` renders as an SVG layer over the sheet. `src/lib/routes.ts` `contourRoutes` picks the loops of one depth (native survey vectors when the depth matches, else a grid isoline) for the Routes tab and `buildGpxTracks`. `src/lib/section.ts` samples the bottom profile between two picked points for `SectionChart.tsx` (SVG drawn with attributes only so the PNG export matches). `src/lib/sun.ts` is NOAA solar position; the viewer places the key light at that azimuth with the elevation corrected for exaggeration (`tan θ' = E · tan θ`) so shadow lengths on the ground stay true, and the shadow camera is widened from Three's ±5 default to cover the model. `src/lib/wind.ts` walks the shoreline isoline and returns the runs whose land-side normal faces the wind. `src/lib/layers.ts` builds the laser-cut pack from a field padded with −1e9 so every isoline closes; sheet area uses a nesting-parity even-odd sum because marching-squares rings have no consistent winding; `src/lib/dxf.ts` writes R12 POLYLINE/TEXT. `src/lib/soundings.ts` parses CSV/TSV/GPX soundings in the browser; the server does the interpolation.

**Multi-material export** — `generateWatertightSTLMesh(data, opts, quadMask?)` builds any set of grid quads as a closed solid by walling every edge whose neighbour quad is outside the mask; `generateSplitMeshes` uses `quadMaterial` (a quad is lake when ≥3 corners are water) to produce mating land and lake solids. `encode3MF` writes a stored zip with one 3MF object per part plus a root object of components and `basematerials` colours.

**SVG map (`server/topoMapGenerator.ts`)** — generated server-side and returned as `svgTopoMap` in the terrain JSON. Everything in it is derived from the grid: a hypsometric PNG raster (encoded by `server/png.ts`, no image library) under real contour paths, real bounds in DMS, a scale bar from `physicalWidthKm`. Do not reintroduce hard-coded shapes.

**Scale contract** — vertical exaggeration means the same thing in the viewer and the STL: 1.0x = the same units-per-metre vertically as horizontally. `depthBoost` (`src/lib/relief.ts`) multiplies the bed's drop below the water surface only; `boostedElevation`/`boostedMinElevation` are the single source for both the viewer's mesh heights and the exporter's relief, so keep them in sync through that module. The viewer keeps an unboosted `shaped` grid for contour levels and drapes lines on the boosted one. `Lake3DViewer` maps the east-west frame to 100 scene units; `stlExporter` maps it to `targetWidthMm`. `suggestExaggeration` picks a value that gives ~14% of the width as relief because Midwestern lakes are nearly flat at true scale. STL frame: +X east, +Y north, +Z up, flat base at z=0.

**Frontend (`src/App.tsx`)** owns all state (query, view mode `3d`/`topo`/`split`, viewer controls) and passes it down; `Lake3DViewer` splits work into separate effects (terrain+base+contours rebuild, water surface rebuild, wireframe toggle, water opacity) so slider changes only rebuild what they affect. The STL dialog is mounted only while open because it computes the full mesh in `useMemo`.

## Conventions & gotchas

- `@` import alias resolves to the project root, not `src/` (`vite.config.ts`). Server code imports browser-shared types/libs from `../src/...`.
- There is no `@types/react`, and `strict` is off, so `React` is `any`: component props are not checked against their interfaces and destructured defaults widen (`pickMode = 'none'` becomes `string`). Type a default explicitly (`pickMode = 'none' as PickMode`) when a literal union matters.
- Do not modify the `DISABLE_HMR` handling in `vite.config.ts`.
- LLM access goes through `server/llm.ts` only: `LLM_PROVIDER` selects Anthropic (official SDK, `client.beta.messages` with server-side fallbacks), Gemini (`@google/genai`), or any OpenAI-compatible endpoint via `fetch`. Defaults per provider live in `DEFAULT_MODELS`; override with `LLM_MODEL`. A key starting with `MY_`, `your-` or `your_` is treated as a placeholder and counts as unset. Never call a provider SDK from anywhere else.
- Nominatim usage policy: keep the `User-Agent` set (`GEODATA_USER_AGENT`), never bypass `nominatimFetch` (serialised, 1.1 s spacing, one retry on 429), and keep the OpenStreetMap, USGS and Indiana DNR attribution in the UI footer and SVG.
- Public services used at runtime (all keyless): Nominatim, `elevation.nationalmap.gov` (3DEP), `s3.amazonaws.com/elevation-tiles-prod` (Terrarium), `gisdata.in.gov` (IDNR feature service), `in.gov/dnr` (depth-map PDF index), `en.wikipedia.org`, `wikidata.org`. The Indiana `maps.indiana.edu` / `imagery.gis.in.gov` servers reset connections from some networks; 3DEP carries the same LiDAR, so they are not used.
- Env vars `.env.example` does not list: `LAKE_CACHE_DISABLED=true` bypasses the disk cache; `DEM_3DEP_URL` and `IDNR_BATHYMETRY_URL` override the service endpoints.
- Styling is Tailwind v4 through `@tailwindcss/vite`; there is no `tailwind.config` and `src/index.css` is just the `@import`.
- `metadata.json` and `public/assets/aistudio/` are Google AI Studio hosting artifacts; leave them.
- The README's API Reference table lists every `/api` route; update it when adding one.
